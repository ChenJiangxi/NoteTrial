# NoteTrial

**产品功能：**
发小红书之前，用 AI 模拟真实用户，提前做一次 A/B crowd test。
通过**平台校准后的受众模拟**，帮助用户在“发帖前”判断：哪一版内容更可能在小红书获得更高互动（点赞 / 收藏 / 评论）。

**目标用户：**
小红书个人创作者 / 小团队 / 中小商家 / 独立开发者，缺乏系统化运营能力。

## 4. 功能模块拆解

------

## 4.1 左栏：对话 / 任务定义（必选）

**目的**

- 把“随便写文案” → 变成 **有明确测试目标的内容实验**
- 为后续的**受众模拟 + 平台校准**提供条件

**最小功能**

- 对话式输入（Chat UI）
- 用户描述：
  - 选题
  - 目标受众
  - 核心优化目标（点赞 / 收藏 / 转化）

**示例**

```
我想写一篇给程序员看的副业内容，
主要想提高收藏率，
内容不要太像广告。
（传入图片）
```

**系统结构化为 Task Spec（内部）**

```json
{
  "platform": "xiaohongshu",
  "goal": "maximize_save",
  "audience": "程序员 / 打工人",
  "tone_constraints": ["不营销", "真实"],
  "test_type": "A/B"
}
```

👉 该 Task Spec **不仅用于 LLM 生成内容**，
👉 还会作为 **CrowdTest 评分与平台校准的条件输入**。

------

## 4.2 中栏：内容编辑区（必选）

### 功能 1：A/B 内容输入

- Content A（主版本）
- Content B（对照版本）
- 支持字段：
  - 封面（图片）
  - 标题
  - 正文
  - 标签（文本）

### 功能 2：AI 辅助生成

- 基于 A 生成 B，例如：
  - 不同开头 hook
  - 更偏“种草 / 可抄作业”的版本
  - 更偏“理性经验总结”的版本

> MVP 阶段只需一个操作：
> **“基于当前内容生成一个对照版本”**

------

## 4.3 右栏：CrowdTest（核心模块）

> ⚠️ **关键说明（理解数据接入的关键）**
> CrowdTest 并不是一个“直接预测真实流量”的模型，
> 而是一个 **“受众模拟 × 平台校准 × A/B 排序”的决策模块**。

------

### 4.3.1 Audience Simulation（核心）

**输入**

- Task Spec
- Content A / Content B

**基础逻辑（通用层）**

- 构造多个受众 persona（基于 Task Spec）
- 对 A / B 分别进行多 persona 模拟判断
- 产出 **相对偏好分数**（而非绝对预测）

**这一层关注的是：**

- 内容是否“对目标人群有吸引力”
- 是跨平台通用的判断

------

### 4.3.2 【新增】Xiaohongshu Platform Calibration（真实数据接入点）

> ✅ **真实小红书数据只在这一层接入**
> ❌ 不用于实时预测
> ❌ 不直接暴露给用户
> ❌ 不作为模型训练标签

#### 校准层的作用（非常明确）

- 把“通用受众偏好分数”
  → **校准为“符合小红书平台分布的偏好分数”**

换句话说：

> **真实数据不是用来“算结果”，而是用来“修正评分规则”。**

------

#### 校准所使用的真实数据类型（MVP 级）

**数据来源（低频、小样本）**

- 指定话题下的小红书历史笔记（Top N，如 50–200 条）
- 对应的：
  - 标题长度分布
  - 开头结构（是否数字 / 痛点 / 对照）
  - emoji / 口语特征
  - 收藏 / 点赞比例区间（不需要精确）

**这些数据用于：**

- 建立 **平台结构与语言分布的先验**
- 调整 Audience Simulation 的打分权重

------

#### 技术位置（非常重要）

```
Audience Simulation (LLM / predictor)
          ↓
XHS Calibration Layer  ← 使用 MCP + 样本统计
          ↓
Final A/B Score
```

**而不是：**

```
抓数据 → 预测真实点赞数（❌ 不做）
```

------

#### MCP（xiaohongshu-mcp）的正确使用方式

> https://github.com/xpzouying/xiaohongshu-mcp

**在 MVP 中的定位：**

- 不作为“自动化发帖或实时监控工具”
- 只用于：
  - 抽取平台语言风格
  - 分析爆款结构分布
  - 生成 **platform-conditioned prompt / scoring rule**

👉 MCP 是 **校准器（calibrator）**，不是执行器。

------

### 4.3.3 诊断解释（比“分数”更重要）

**目的**

- 告诉用户：
  👉 *为什么* B 比 A 更可能在小红书跑出来

**示例解释**

- B 的前 2 行更符合小红书高收藏笔记的常见结构
- A 的表达更像“经验分享”，但缺乏明确可执行点
- 对当前目标受众：
  - “可抄步骤”权重高于“个人故事”

👉 这一步决定产品是否“可信”。

------

### 4.3.4 改写建议（必选）

**输出结构**

- 标题候选 × 3（平台风格约束）
- 开头 hook × 2（结构级建议）
- 明确指出：
  - 哪一段可以压缩
  - 哪一段应前置

**示例**

```
建议将第 3 段的背景铺垫压缩为一句，
并在开头加入具体数字或结果型描述，
更贴近当前平台高收藏内容的结构分布。
```

------

## 5. MVP 阶段对真实数据的“边界定义”（防止你走偏）

- ✅ 使用真实小红书内容 **校准评分规则**
- ✅ 使用真实话术优化 prompt
- ❌ 不预测具体点赞数
- ❌ 不承诺“爆款保证”
- ❌ 不做用户级账号监控
